Умные решения. Недорогое исполнение.

Сильная модель разбирает задачу и проверяет результат. Kimi и GLM выполняют правки через OMP. Требования и решения сохраняются в Beads. Для провайдеров моделей нужны личные аккаунты, подписки или квоты.

Как выглядит цикл

Это пример переходов, не live-пайплайн. После реализации результат снова проверяет Sol и принимает владелец.

  1. Hermes Запрос. Формулировка задачи и уточнения.
  2. Beads Контракт. Сохраняются требования, scope и критерии приёмки.
  3. Sol Планирование. openai-codex/gpt-6.1-sol разбивает задачу и готовит план.
  4. Owner go gate Одобрение. Владелец проверяет план и даёт добро перед реализацией.
  5. OpenCode Go Реализация. Kimi K2.7 Code пишет код. GLM-5.3 Flash помогает в разведке и мелких задачах, при необходимости заменяет основную модель. Всё выполняется через OMP.
  6. Review и приёмка Sol ревьюит результат. Владелец принимает или отправляет на доработку.

Роли

Hermes

Вход и диалог. Здесь появляется первая формулировка задачи и уточнения.

Beads

Долговечный контракт задачи. Хранит scope, критерии и историю принятых решений.

Sol

openai-codex/gpt-6.1-sol. Планирует архитектуру, разбивает работу и ревьюит код.

OpenCode Go

Kimi K2.7 Code для реализации. GLM-5.3 Flash для разведки, быстрых задач и execution fallback.

OMP oh-my-pi

Оркестратор. Распределяет задачи и запускает исполнителей через task.

Что понадобится

Тот же набор сервисов, на котором работает автор. Подписки и аккаунты оформляются на себя: свои ключи, общие доступы не передаются.

Ответы на вопросы

Какие подписки нужны?

Для провайдеров моделей нужны собственные аккаунты, авторизация и подписки или доступные квоты. Условия и доступность определяют провайдеры.

Кто одобряет результат?

Владелец. Перед реализацией и после неё стоит owner go gate. Доступ инструментов к данным и API контролируется настройками и владельцем.

Как здесь устроена privacy?

Эта страница ничего не отправляет. Prompts и вызовы tools не sandbox: доступ к данным и API контролируется настройками и владельцем. Headless-режим always-ask может блокировать запуск, пока не получит подтверждение.

На каких платформах работает?

Целевые платформы: macOS, Linux и WSL2. Проверено только на macOS. Чистая установка и интеграция с провайдерами не гарантируются.

Можно ли запускать unattended?

По умолчанию рассчитывайте на участие владельца. Режим always-ask может ждать подтверждения и не будет удовлетворён автоматически.
